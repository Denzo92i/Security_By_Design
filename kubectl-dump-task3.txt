$ kubectl port-forward svc/krakend-gateway 8000:8000 &

$ curl -s -o /dev/null -w "%{http_code}" \
    -H "Authorization: Bearer <ADMIN_JWT>" \
    http://localhost:8000/customers
200

$ curl -s -o /dev/null -w "%{http_code}" \
    -X POST \
    -H "Authorization: Bearer <ADMIN_JWT>" \
    -H "Content-Type: application/json" \
    -d '{"name":"Alice","email":"alice@example.com"}' \
    http://localhost:8000/customers
201

$ curl -s -o /dev/null -w "%{http_code}" \
    -H "Authorization: Bearer <CUSTOMER_JWT>" \
    http://localhost:8000/restaurants
200

$ curl -s -o /dev/null -w "%{http_code}" \
    -X POST \
    -H "Authorization: Bearer <CUSTOMER_JWT>" \
    -H "Content-Type: application/json" \
    -d '{"name":"The Pond"}' \
    http://localhost:8000/restaurants
403

Note: JWT validation is enforced by Spring Security on the backend API pods.
KrakenD forwards the Authorization header verbatim to the upstream service.
The Spring Boot resource server validates the token against Keycloak's JWKS
endpoint: http://keycloak:8080/realms/foodndeliv/protocol/openid-connect/certs
